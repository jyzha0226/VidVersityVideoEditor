# VidVersityVideoEditor

## Overview

This branch focuses on a frontend revamp of the VidVersity editor shell while keeping the current project as a browser-side prototype. The work in `UI_revamp` improves the editing experience, adds route-based library pages, and restores or preserves the demo behaviors that still exist in the current product.

## What Changed

### Editor UI and Timeline

- Reworked the editor into a three-panel layout:
  - left navigation
  - center preview and timeline workspace
  - right AI/subtitle panel
- Added a transport bar above the timeline with:
  - play and pause
  - previous and next frame stepping
  - current time and total duration
  - timeline zoom in and out
- Rebuilt the timeline to feel more like a video editor:
  - draggable and clickable playhead
  - video thumbnails generated from the uploaded file
  - waveform generated from the uploaded file audio
  - cleaner bottom-anchored timeline layout
- Added Guided Mode tooltips for toolbar actions when Guided Mode is enabled.
- Added an undo stack for timeline and subtitle edits.

### Drafts and Archive Pages

- Added dedicated route-based pages for:
  - `/drafts`
  - `/archive`
- Kept the shared top bar and navigation shell consistent across editor and library pages.
- Added mock video card libraries for Drafts and Archive.
- Drafts page now has an `Upload Video` action that opens the file picker and routes into the editor with the chosen video preloaded.
- Archive page now has a disabled-by-default `Recover Video` action that becomes enabled when an archived video card is selected, then routes back to the editor as a placeholder flow.

### Theming

- Implemented actual light and dark mode behavior for the app surfaces instead of only toggling the icon.
- Themed:
  - editor shell
  - sidebars
  - cards
  - toolbar
  - timeline
  - subtitle panel
  - Guided Mode tooltips

### Placeholder Product Actions

- Added `Save Draft` and `Archive Video` buttons in the editor sidebar as UI placeholders for future persistence flows.
- These actions are not yet backed by storage or a backend.

## Technical Notes

### Media Timeline

The timeline remains frontend-only:

- thumbnails are generated by seeking a hidden browser video element and drawing frames to a canvas
- waveform data is generated with the Web Audio API from the uploaded file
- no FFmpeg pipeline or export rendering has been added yet

This means the timeline is now file-aware for preview purposes, but edits are still in-memory UI state rather than real media processing.

### Route Handoff

The Drafts page upload flow currently passes a temporary object URL into the editor route state. The editor preview accepts this incoming URL and initializes the preview with it.

This is a lightweight bridge for the prototype and should likely be replaced later with one of:

- IndexedDB-backed local draft persistence
- backend-managed draft records and uploads
- signed object storage URLs if media moves to cloud storage

### Persistence Direction

No draft or archive persistence is implemented yet.

Recommended future direction:

- use a backend data store for project metadata and edit state
- store timeline edits, subtitle edits, and project metadata separately from raw media files
- use AWS-backed storage and database services when the team is ready to make drafts and archive state real across sessions/devices
